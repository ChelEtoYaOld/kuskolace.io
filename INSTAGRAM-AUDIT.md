# Instagram: фотографии и проверка синхронизации

Проверено 12 октября 2026 года по исходникам и готовым серверным JS-модулям.

## Фотографии
Три снимка скачаны из публичной сетки @kuskolace. Основной снимок с инжиром использован в первом экране. Все три размещены в новой галерее с прямыми ссылками на публикации. Файлы хранятся локально в public/images/instagram; sources.json содержит источники и дату загрузки. Это ручная подборка, не автоматическая синхронизация. Подписи описывают изображения, а не воспроизводят тексты публикаций. Лайки не придуманы и не показаны.

## Найденные ошибки
- AdminHome.manualSyncInstagram не вызывал Instagram: записывал только ложную успешную дату и статус.
- AdminInstagramIntegration.triggerInstagramSync создавал фиксированный тестовый пост со случайными лайками на каждое нажатие. Повторный запуск плодил записи.
- OAuth, вызовы Instagram API, хранение/обновление токена и фоновое расписание в изученном коде отсутствуют.
- autoSync был только флагом БД; успешный статус можно было выставить из формы.
- Исходные seed-данные содержат демонстрационные посты, помеченные isFromApi=true.

## Защитные исправления
Обе кнопки синхронизации и включение автообновления теперь возвращают понятную ошибку без записи постов или успешной даты. API-режим и ручная установка статуса «авторизовано» отклоняются. Ответы административной конфигурации показывают реальное состояние: не подключено, без автообновления и последней успешной даты. Ручное редактирование сохранено; оно не может пометить пост как импортированный API. Известные демонстрационные записи и старые записи с ложным isFromApi не отображаются в публичной галерее. Данные из БД не удалены. Защита внесена также в готовые серверные JS-модули, поскольку dev-host загружает именно их.

## Проверки
Регрессионные тесты отдельно запускают исходные TS и серверные JS с подставной БД: 5 недоступных операций отклоняются без записей; старые ложные статусы не выдаются клиенту как успешные. Проверены синтаксис изменённых файлов, SSR галереи и наличие трёх локальных фотографий. Тест: node tests/instagram-regression.cjs после установки зависимостей проекта.

## Что ещё требуется для настоящей синхронизации
Нужны разрешённое подключение аккаунта владельцем, серверная конфигурация Instagram API, импорт с обновлением по уникальному ID публикации, обновление истекающих медиа-ссылок, обработка ошибок/лимитов и реальное фоновое задание. Этот патч не реализует и не активирует API. Не вводите секретный токен в чат: его следует хранить в секретах серверного окружения. Рабочий сервер и живая БД не были доступны; онлайн-синхронизация не проверялась. Перед развёртыванием выполнить штатную сборку проекта (pnpm run gen_rpc и pnpm run build:server) в его рабочей среде.
